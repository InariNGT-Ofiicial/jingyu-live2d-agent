## 迁移顺序

| 顺序 | 可复用内容 | 对鲸语的价值 | 接入方式与约束 |
|---|---|---|---|
| 1 | Runtime Probe 的基线采样、受控参数注入、幅值与恢复检查 | 快速确定模型究竟能动哪些部分，避免动作结束后残留 | 借鉴测试流程，改接鲸语的运行时；上游直接依赖 window.DSH_L2D，不能原样运行于鲸语。保持现有作者物理输出限制，先在隔离调试预览验证。 |
| 2 | Model Adapter 的模型/通道映射及参数集合差异检测 | 将同一语义动作适配不同模型，并识别参数删除或范围变化 | 复用映射格式与差异检测思路，对接现有 model_profile 和 compiler；不为单模型一次性搬入整套数据库。 |
| 3 | Hard/Soft 双层幅度窗口 | 分清模型真实上下限与推荐表演幅度，避免把小幅实测误当模型能力上限 | 使用鲸语实际参数范围作为 Hard；Soft 作为可调风格建议。迁移前修复字段缺失与非有限范围处理。 |
| 4 | GIF 逐帧时间、差异曲线、关键帧候选 | 帮助从参考动作提取快慢节奏，辅助预设编排 | 先做只读分析入口；像素差异不是动作语义，也不是模型参数。先修静止峰值问题，验证变帧延时/透明帧后再接编排。 |
| 后续 | 动作/素材 SQLite、语义标签库 | 动作数量增长后提供检索和来源管理 | 当前已有预设文件与导入接口，先保留，避免同时维护两套数据源。 |

不迁入角色人格、行为循环、任务编排或上游审核流程。工作台继续负责角色呈现、动作/语音执行与工具接口，决策由外部 Agent 负责。

## 本机验证

使用 Node 24.22.1，日志位于 `.local/checks/dsh-sync-1105/`：

- Model Adapter：11 项通过。
- 双层边界：12 项通过。
- GIF 分析：上游汇报 8 项通过，其中真实 GIF 集成因其硬编码的本地素材不存在而跳过；实际执行 7 项。没有据此宣称真实素材入库已验证。

补充复现：

1. `checkInjection({}, 999)` 返回 `ok: true`。实现只检查边界 `!== null`，未覆盖 `undefined`；因此不能直接把这个函数当作任意外部 JSON 的校验入口。数据库正常行通常有显式 null，这一缺陷在脱离数据库迁移时尤其相关。
2. `analyzeTiming([{diffScore:null},{diffScore:0},{diffScore:0}])` 返回 `startFrame:null, endFrame:null, peakFrame:1`。静止序列仍给出峰值索引，迁移时应统一为空。
3. 上游 `run-action.mjs` 对无法映射的表情/轨道采用跳过，并可凭部分通道活动得出 PASS。鲸语应分别显示完整执行、部分执行和失败，不能将该 PASS 直接作为整段动作验收。
4. [-1,1] 线性映射把零映到 min/max 中点；不是所有参数的默认值都在中点。接入鲸语前应明确各通道的中性值，避免零输入改变服装等开关参数。
